# Техническая документация Arlade: Как это работает

## 1. Инициализация и запуск

### 1.1 Точка входа (index.html)
Структура HTML определяет три основных контейнера:
- topPanel: Для HUD (здоровье и т.д.)
- gameContainer: Для игрового canvas
- gameLog: Для вывода игровых сообщений

### 1.2 Запуск игры
1. Создаётся экземпляр класса Game
2. Создаются основные системы:
   - Camera
   - Renderer
   - CollisionSystem
   - InputSystem
3. При инициализации загружаются:
   - Карты из maps.json
   - Глифы из glyphs.json
4. После загрузки ресурсов:
   - Если enableMainMenu = true: показывается главное меню
   - Иначе: сразу запускается игра через game.startGame()

## 2. Игровой цикл

### 2.1 Основной цикл (game.js)
1. Расчёт времени между кадрами
2. Если игра на паузе - пропускаем обновление
3. Обновление систем:
   - InputSystem
   - HUD
   - Camera (зум)
4. Обработка анимаций:
   - Движение игрока
   - Атаки игрока
5. Обновление врагов и их анимаций
6. Проверка завершения анимаций
7. Обновление видимости
8. Рендеринг
9. Планирование следующего кадра

### 2.2 Порядок выполнения хода
1. Ход игрока:
   - Проверка возможности хода
   - Проверка атаки
   - Выполнение движения
   - Запуск хода противников

2. Ход противников:
   - Сброс очков действий
   - Поиск активного врага
   - Обновление видимости и состояния
   - Атака или движение
   - Переход к следующему врагу или конец хода

## 3. Система противников

### 3.1 Типы врагов
1. Зомби:
   - Не летает
   - Здоровье: 100
   - Радиус патруля: 5
   - Дальность зрения: 4
   - Действий за ход: -2 (медленный)
   - Длительность памяти: 5 ходов

2. Летучая мышь:
   - Летает
   - Здоровье: 50
   - Радиус патруля: 2
   - Дальность зрения: 2
   - Действий за ход: 2 (быстрый)
   - Длительность памяти: 3 хода

### 3.2 Состояния ИИ
1. Патруль:
   - Выбор точки патрулирования
   - Поиск пути к точке
   - Движение по пути
   - Выбор новой точки при достижении цели

2. Преследование:
   - Поиск пути к игроку
   - Движение по пути
   - Прямое движение если путь не найден

3. Исследование:
   - Движение к последней известной позиции игрока
   - Переход в патруль при достижении позиции
   - Возврат к патрулю если позиция неизвестна

## 4. Система видимости

### 4.1 Параметры
- VIEW_DISTANCE = 4
- VIEW_ANGLE = Math.PI / 2 (90 градусов)
- INITIAL_VISION_RADIUS = 3

### 4.2 Карта видимости
- 0: не исследовано
- 1: исследовано но не видно
- 2: видно сейчас

### 4.3 Обновление видимости
1. Сброс видимых тайлов в состояние "исследовано"
2. Проверка видимости в радиусе:
   - Для стен только проверка расстояния
   - Для остального проверка прямой видимости
3. Особая обработка дверей и стен:
   - Проверка видимости до клетки перед объектом
   - Прямая видимость при близком расстоянии

## 5. Система рендеринга

### 5.1 Порядок отрисовки
1. Очистка canvas
2. Определение видимой области
3. Сбор объектов для отрисовки
4. Отрисовка объектов
5. Наложение тумана войны
6. Отрисовка отладочной информации

### 5.2 Система глифов
- Матрица 16x16 пикселей
- Каждый пиксель может быть:
  - Прозрачным (-)
  - Цветным (буква = цвет из палитры)
- Кэширование отрисованных глифов
- Масштабирование под размер тайла

## 6. Система ввода

### 6.1 Клавиши управления
- WASD/Стрелки: движение
- QEZC: диагональное движение
- L: режим осмотра
- Shift+O: открыть дверь
- Shift+C: закрыть дверь
- Пробел: контекстное меню
- +/-: зум камеры
- Delete: меню отладки
- Escape: меню паузы

### 6.2 Обработка движения
1. Проверка задержки между ходами
2. Определение направления
3. Режим осмотра:
   - Движение рамки в пределах видимой области
4. Обычный режим:
   - Проверка возможности движения
   - Выполнение хода

## 7. Форматы данных

### 7.1 Карты (maps.json)
- objects: определения типов объектов
  - glyph: имя глифа
  - type: тип объекта
  - blocks_movement: блокирует движение
  - blocks_light: блокирует свет
  - z_index: слой отрисовки
  - description: описание для режима осмотра
- layout: массив строк с картой

### 7.2 Глифы (glyphs.json)
- pixels: матрица 16x16 с символами цветов
- colors: соответствие символов и цветов

## 8. Взаимодействие систем

### 8.1 Движение игрока
1. InputSystem -> Game.tryMove
2. Game.tryMove -> CollisionSystem
3. При успехе:
   - Обновление координат
   - Запуск анимации
   - Обновление видимости
   - Ход противников
4. Renderer -> отрисовка

### 8.2 Атака
1. Game.tryMove -> CombatSystem
2. При успехе:
   - Анимация атаки
   - Нанесение урона
   - Обновление HUD
   - Ход противников

### 8.3 Ход противников
1. Сброс очков действий
2. Для каждого врага:
   - Проверка видимости
   - Обновление ИИ
   - Действие
   - Анимации
3. Возврат хода игроку
